# ASR-001 Operator Review Change Control

**Version:** 1.0  
**Baseline:** ASR-001 Working Draft v0.2

## 1. Frozen Baseline

Before a review wave begins, the package records SHA-256 hashes for:

- Working Draft v0.2;
- clause catalog v0.2;
- clause-to-field map v0.2;
- profile model and schema v0.2;
- internal-trial results;
- friction register;
- reviewer package artifacts.

Review comments reference this frozen baseline.

## 2. Change Classes

### Editorial

No semantic or implementation effect.

### Clarification

Reduces ambiguity without changing applicability or obligation.

### Conditionality Change

Changes a trigger, applicability state, or conditional dependency.

### Evidence Change

Changes evidence requirement, provenance, uncertainty, or verification.

### Implementation Change

Changes a field, schema rule, identifier, serialization, or validation behavior.

### Normative Change

Changes a candidate obligation's substantive effect.

### Scope Change

Expands or narrows the approved subject, domains, uses, or exclusions.

## 3. Version Effects

- editorial and bounded clarification can produce a patch Working Draft revision;
- conditionality, evidence, implementation, or normative change produces at least a minor Working Draft revision;
- clause removal, incompatible field change, or scope change requires an explicit compatibility and governance decision;
- Public Review status is never created by version numbering alone.

## 4. Identifier Stability

Clause identifiers remain stable when meaning is clarified or narrowed.

A clause is not silently repurposed. A materially different obligation receives a recorded replacement or split decision.

## 5. Historical Preservation

Earlier Working Drafts, catalogs, schemas, review baselines, and dispositions remain immutable.

Corrections use supersession rather than overwrite.

## 6. Review Wave Isolation

Changes are not applied to the active review baseline while comments are still being collected.

Urgent correction requires:

- a review-wave pause;
- a new baseline manifest;
- written notification to every active reviewer;
- explicit carry-over treatment for existing comments.

## 7. Conflict and Attribution

A change record identifies whether the supporting comment is:

- named;
- role-attributed;
- anonymous;
- internal-only.

Conflict declarations inform interpretation but do not automatically accept or reject a comment.

## 8. Owner Authority

The owner ratifies:

- blocking-issue dispositions;
- scope holds;
- incompatible changes;
- transition to a new Working Draft baseline;
- any future Public Review authorization.

## 9. No Adoption Claim

A reviewer-requested change, even when accepted, does not establish reviewer or organizational adoption.
