# ASR-001 Informative Examples Boundary

**Version:** 0.1  
**Status:** Informative-content rule

## 1. Purpose

Examples explain a clause or profile relation without becoming hidden requirements.

## 2. Separation Rule

Every example is labeled informative and separated from candidate requirement text.

An example does not:

- add an obligation;
- narrow an obligation;
- create a score;
- establish category membership;
- certify a product;
- define an unapproved technical threshold.

## 3. Boundary Cases

BC-001–BC-020 can be cited to:

- explain why a clause exists;
- show a valid uncertainty state;
- show object-lock failure;
- illustrate conditional applicability;
- demonstrate evidence limitations.

They are not templates that every implementation must resemble.

## 4. Provider Examples

A named provider example includes:

- source and access date;
- configuration scope;
- provider-claim attribution where applicable;
- limitations;
- statement that inclusion is not endorsement.

## 5. Synthetic Examples

Synthetic examples are preferred when a real provider name adds no evidence value.

Synthetic examples are clearly labeled and cannot be cited as market facts.
